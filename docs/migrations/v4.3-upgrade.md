# Upgrade notes: v4.3

Steps an operator runs when upgrading an installation to v4.3, and the boot
migration to know about. Apply the steps after the new version is deployed;
the update itself never waits on them.

## 1. Backfill the original dimensions of the image stock

Since v4.3 every uploaded image stores the width and height of its original
(`width`, `height` on the medium) — the numbers the hero layout of the
storefront sizes an image by. Media uploaded before this version carry `null`
until the backfill has run:

```bash
node src/cli/media-cli.js backfill-dimensions --dry-run
node src/cli/media-cli.js backfill-dimensions
```

The command reads each image once at the provider it lives on and writes the
two numbers, nothing else — no file, storage key or variant is touched. It only
looks at images sharp can read; documents and ICO favicons have no dimensions
and stay `null`. It is idempotent: media that already carry their dimensions
are skipped without being read, so a second run reports `0 processed` and the
whole image stock as skipped. `--tenant <id>` restricts
the run to one tenant, and a medium whose bytes do not decode is listed as an
error and left as it is.

Until the backfill has run, a hero layout referencing an old image is exported
with `width`/`height: null`; nothing else depends on the numbers.

## 2. The Hero title becomes the Portal Name

The two text fields of the catalog's Hero, `hero.title` and `hero.subtitle`,
are gone. The Hero is a Hero Layout now (`heroLayout` on the catalog), and
until an admin composes one the backend derives the default: the branding
logo, the **Portal Name** — the instance catalog's `name` — as the title, and
the slogan „Entdecken Sie unsere Angebote" / "Discover our offers".

The boot migration `10-09-2026-hero-title-to-portal-name` runs once at the
first start of v4.3 and needs no operator step:

- it copies `hero.title` into the instance catalog's `name` when that is
  empty, so an installation that only ever had a Hero title keeps it as its
  Portal Name;
- it removes the `hero` key from every catalog. The subtitle is dropped; the
  default slogan replaces it.

Running it again is a no-op. Afterwards, check the Portal Name in the general
settings of the admin UI: it is load-bearing now — browser title, Hero title,
auth pages — and the instance catalog can no longer be saved without one.
