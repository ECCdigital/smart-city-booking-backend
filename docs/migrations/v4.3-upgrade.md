# Upgrade notes: v4.3

Steps an operator runs when upgrading an installation to v4.3. Apply them after
the new version is deployed; none of them is a boot migration, so the update
itself never waits on them.

## 1. Backfill the original dimensions of the image stock

Since v4.3 every uploaded image stores the width and height of its original
(`width`, `height` on the medium) — the numbers the hero layout of the
storefront sizes an image by. Media uploaded before this version carry `null`
until the backfill has run:

```bash
node src/cli/media-cli.js backfill-dimensions --dry-run
node src/cli/media-cli.js backfill-dimensions
```

The command reads each image once at the provider it lives on and writes the
two numbers, nothing else — no file, storage key or variant is touched. It only
looks at images sharp can read; documents and ICO favicons have no dimensions
and stay `null`. It is idempotent: media that already carry their dimensions
are skipped without being read, so a second run reports `0 processed` and the
whole image stock as skipped. `--tenant <id>` restricts
the run to one tenant, and a medium whose bytes do not decode is listed as an
error and left as it is.

Until the backfill has run, a hero layout referencing an old image is exported
with `width`/`height: null`; nothing else depends on the numbers.
