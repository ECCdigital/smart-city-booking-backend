# Upgrade notes: v4.4

What an operator needs to know when upgrading an installation to v4.4.

## Salto doors offer only „Per App“

Change of the access points
([ECCdigital/tickets#499](https://github.com/ECCdigital/tickets/issues/499)).
A Salto KS door offers the mode `remote` alone, at every lock type, keypad
locks included. The platform no longer creates a guest with a PIN in Salto KS
for a booking: that path never worked, since every Salto PIN hangs on a user
and the platform creates none.

There is no migration. An access point still stored with `authorization` or
`both` is skipped by the provisioning as not supported, and saving it again
with one of those modes is refused as `unsupported_mode`. The grant cleanup
skips open Salto grants, because the provider offers no revoke any more.

### Before the deploy

Check every installation with `mongosh` against its database. Salto access
points with a mode other than `remote`:

```js
db.accesspoints.find({
  provider: "salto-ks",
  mode: { $in: ["authorization", "both"] },
});
```

Open Salto grants of bookings:

```js
db.bookings.find({
  accessInfo: {
    $elemMatch: { provider: "salto-ks", grant: { $ne: null }, revokedAt: null },
  },
});
```

Both have to come back empty. Otherwise:

- set each such access point to `remote`;
- clean up each open grant by hand in Salto KS, since the cleanup no longer
  takes it back.
