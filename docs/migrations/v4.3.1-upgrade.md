# Upgrade notes: v4.3.1

What an operator and a client developer need to know when upgrading an
installation from v4.3.0 to v4.3.1.

## A self-booking cannot start in the past

Change of the public API ([ECCdigital/tickets#188](https://github.com/ECCdigital/tickets/issues/188)).
The self-booking refuses a begin before now for a bookable with a booking
period (schedule, time period, long range, block period) with the new reason
`checkout.time_in_past`, check type `time-in-past`:

- v1 (`POST /api/:tenant/checkout`, `/checkout/validateItem`,
  `/checkout/group`) answers `400` with the reason as its body; on
  `validateItem` as `{ "error": "checkout.time_in_past", … }`.
- v2 (`/api/v2/:tenant/checkout`, `/validate/:id`, `/group`) answers as for
  every refusal, `/validate-group` the same in the past attempt:

```json
{
  "success": false,
  "error": { "reason": "checkout.time_in_past", "checkType": "time-in-past" }
}
```

- `GET /api/:tenant/bookables/:id/occupancy` answers a past window as not
  available.

Until v4.3.0 a begin in the past was refused only for a bookable with a
preparation lead time. A client that knows no text for the reason falls back
to its general one; Admin UI v4.3.1 and Storefront v1.2.1 name it and no
longer take a typed date before today. The manual booking (`POST` and `PUT
/api/:tenant/bookings`) books backwards as before.
