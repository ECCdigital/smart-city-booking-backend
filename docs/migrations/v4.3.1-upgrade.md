# Upgrade notes: v4.3.1

What an operator does when upgrading an installation from v4.3.0 to v4.3.1.

## Checkout behind a login answers 401

Change of the public API
([ECCdigital/tickets#123](https://github.com/ECCdigital/tickets/issues/123)).
Until v4.3.0 only the permission check asked for `requiresLogin`; the
completion of a self-booking took a guest's booking of an offer behind a
login. From v4.3.1 on the completion refuses a customer who is not signed in
with `401` and `checkout.login_required` and stores nothing - for the offer
itself and for a mandatory add-on behind a login, simulated too:

- v1 `POST /api/:tenant/checkout` and `POST /api/:tenant/checkout/group`
  answer the reason as text: `checkout.login_required`.
- v2 `POST /api/v2/:tenant/checkout` and `POST /api/v2/:tenant/checkout/group`
  answer `{ "success": false, "error": { "reason": "checkout.login_required", … } }`.
  Every other refusal of the v2 completion keeps answering `200`.

The permission check (`GET /api/:tenant/checkout/permissions/:id`, v2
`GET /api/v2/:tenant/checkout/permissions/:id`) is unchanged, and so is the
manual booking by staff. A client that sends a guest to the completion of
such an offer offers the sign-in on this `401`. It tells it from the `401` of
an expired token (`Token has expired`,
[ECCdigital/tickets#109](https://github.com/ECCdigital/tickets/issues/109))
by the body and renews the token only for that one. No step for the operator.
