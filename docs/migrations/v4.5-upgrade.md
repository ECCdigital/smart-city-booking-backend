# Upgrade notes: v4.5

What an operator needs to know when upgrading an installation to v4.5.

## Refund tiers count in hours

Change of the refund scale
([ECCdigital/tickets#637](https://github.com/ECCdigital/tickets/issues/637)):
its deadlines count in spans of 24 hours up to the start of the booking, no
longer in calendar days. A cancellation at 20:00 the evening before a booking
at 9:00 is 13 hours before the start, no longer „1 day before“; a tier „1
Tag“ now applies only from 24 hours before. A tier can also name hours.

- The migration `02-11-2026-cancellation-refund-tiers-in-hours` turns every
  tier of d days into d × 24 hours. The Admin UI shows them as „d Tage“ as
  before.
- The tier field is `hoursBeforeStart` instead of `daysBeforeStart`. Admin UI
  and Storefront of the matching release read it; older ones do not show
  the scale.
- Roll out backend, Admin UI and Storefront together, and let the deploy wait
  for `/healthz/ready` before it sends traffic. A backend before 4.5 cannot
  read migrated tiers, a 4.5 backend cannot read unmigrated ones: until the
  migration has run, a cancellation, its preview and saving the tenant fail
  with `500`, and an older Admin UI that saves `daysBeforeStart` gets `400`.
- Custom mail and PDF templates keep working. `daysBeforeStart` and
  `daysBeforeStartLabel` count spans of 24 hours; the new
  `timeBeforeStartLabel` reads „2 Tage“ or, below one day, „13 Stunden“.
  The default cancellation receipt no longer says „Kalendertage“ and words
  the calculation like the hint of the cancellation request.
- A tenant that stored the default cancellation template keeps its wording
  „… Kalendertage vor Beginn“, now with spans of 24 hours: every tenant
  created since v4.4.1 stores it. Replace its stored `cancellationTemplate`
  with the default of v4.5, or empty it to render the default; otherwise the
  receipt of a cancellation 13 hours before reads „0 Kalendertage“.
- Rolling back: `down` turns hours into whole days, rounded down. Where two
  tiers fall on the same day (such as 36 and 24 hours), the one with more
  hours stays, so the scale stays valid for v4.4. Its percentage then covers
  the whole day: tiers 5 hours/20 % and 0 hours/0 % become day 0 with 20 %.
